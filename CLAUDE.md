# Orkesta site

This repository builds the current Orkesta studio site. The public site consists of the landing page, project portfolio and detail pages, three service pages, contact, and the privacy notice. Retired `.html` URLs redirect to current routes through `vercel.json`; do not bring their former pages back into the build.

## Commands

```bash
npm ci
npm run dev
npm run build
python3 -m http.server 8080 --directory public
npm test
```

`npm run dev` starts Vercel's local server at `http://localhost:3000/`, including the routing middleware and redirects in `vercel.json`. It requires the Vercel CLI installed on the machine (`npm i -g vercel@latest`) and a local project link. Restart it after switching branches. The Python server is a static preview of `public/` and does not run Vercel middleware. `npm test` runs the build and the Node test suite.

## Source of truth

- `src/rebrand/render.mjs` generates the landing page and route HTML, including SEO metadata and the privacy notice. The root `index.html` is generated by the build; edit the renderer instead.
- `src/rebrand/data.mjs` defines the published projects and services. Every project card and detail route comes from this data.
- `src/rebrand/site.js` handles portfolio filters, demos, the contact and checkout forms, and Vercel Web Analytics. Analytics sends page views only; do not add custom events or personal form fields to it.
- `src/rebrand/commerce-pages.mjs` generates the contact, campaign, terms, privacy and order-status pages. `api/` contains server-only functions for inquiries, checkout, status verification and Mercado Pago webhooks. `src/server/commerce.js` contains shared validation and external API calls. Never expose its secrets to browser bundles.
- `supabase/migrations/` defines the inquiries and orders tables. Both have RLS enabled and no public policies. The server uses a service-role key. Apply migrations to the dedicated Orkestalo project only.
- `src/site.js` handles language switching and direct WhatsApp links. `src/contact.js` constructs WhatsApp URLs.
- `rebrand.css` and `media/` contain the current design system and imagery.
- `scripts/build.mjs` produces the static files in `public/`; Vercel also deploys the functions in `api/`. `public/` and `assets/` are generated and ignored by Git. The build copies only an explicit list of current files; keep that allowlist narrow.
- `sitemap.xml` contains the homepage seed; the build appends current routes. `llms.txt` describes current pages only.

## Publishing

Run `npm test`, commit the change on a branch, push it, open a PR to `main`, and merge. Vercel's Git integration deploys `main` automatically. Verify the resulting production deployment and public URLs. Do not use direct Vercel CLI or API deployments or promotions.

Keep retired URLs as redirects in `vercel.json` rather than publishing old HTML. Add current routes through `src/rebrand/render.mjs` and cover them in the test suite.
